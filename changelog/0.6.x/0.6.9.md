# 0.6.9 — 2026-05-08

Maintenance release. Picks up four framework versions (`@cyanheads/mcp-ts-core` 0.8.15 → 0.8.19) — HTTP SSE leak fix, `ctx.sessionId` for HTTP handlers, `ctx.auth.token` forwarding, telemetry visualization docs. None of the new surfaces require code changes here; the upstream engine bump is the one consumer-visible knock-on.

## Changed

- **Node engine** ≥22 → ≥24 to match `@cyanheads/mcp-ts-core` ^0.8.19.
- **Dockerfile** base pinned `oven/bun:1` → `oven/bun:1.3` (build + production stages) — track Bun engine floor explicitly instead of drifting on the `1` rolling tag.
- **`openalex_search_entities`** — `general_failure` recovery now points at the upstream message + the rejected token rather than a generic "check the docs" hint. Description drops the "(free, unlimited API calls)" aside on `id` lookup.
- **`openalex_analyze_trends`** — `general_failure` recovery names valid `group_by` fields per entity_type (e.g. `publication_year`/`type`/`oa_status` for works, `country_code`/`has_orcid` for authors) instead of pointing at the docs.
- **`openalex_resolve_name`** — `entity_type` output description enumerates the concrete set (`work, author, source, institution, topic, keyword, publisher, funder`); description drops the "Response time ~200ms" aside.
- **`openalex_literature_review`** / **`openalex_research_landscape`** — `topic` arg descriptions now carry a concrete example so LLMs anchor on shape, not on prose.
