# 0.9.0 — 2026-10-18

## Added

- **`author_list`** works `select` field on `openalex_search_entities` and `openalex_get_citation_graph` — each author in authorship order as `{id, display_name, orcid}`, about a tenth the size of `authorships`; never part of the default or `["*"]`. ([#102](https://github.com/cyanheads/openalex-mcp-server/issues/102))
- **`publisher`** sources `select` alias for `host_organization_name`. ([#97](https://github.com/cyanheads/openalex-mcp-server/issues/97))
- **Identifier forms** — OpenAlex record-page and API URLs (`https://openalex.org/works/W…`, `https://api.openalex.org/works/W…`, `http`, or no scheme) resolve as IDs; a ROR resolves to its institution, funder, and publisher records, and a Crossref Funder Registry DOI (`10.13039/…`) to its funder. ([#98](https://github.com/cyanheads/openalex-mcp-server/issues/98), [#99](https://github.com/cyanheads/openalex-mcp-server/issues/99))
- **`generate:iso-codes`** script, which builds `iso-codes.json`.

## Changed

- A filter value that mixes `|` (OR) with an AND — a `+`, or a space on a field where words mean AND — now fails before any request as `mixed_and_or_in_filter_value` on all four filter-taking tools. OpenAlex drops every `|` alternative that ANDs more than one value, so on a multi-valued field such a value returned a partial set (`authorships.institutions.country_code: DE|FR+US` returned only the German works); on a single-valued field such as `type`, `article+review|book` happened to return the right set, and that call is now rejected too. The recovery puts the AND in a second key. ([#107](https://github.com/cyanheads/openalex-mcp-server/issues/107))
- **`upstream_unavailable`** replaces `upstream_invalid_params_other` when a semantic search's query embedding fails upstream, with a keyword-search fallback in the recovery. ([#96](https://github.com/cyanheads/openalex-mcp-server/issues/96))
- **`upstream_plan_required`** replaces `rate_limited` for a filter OpenAlex serves only on a paid plan (`created_date`, `updated_date`, and their `from_`/`to_` forms); it fails on the first request instead of retrying. ([#114](https://github.com/cyanheads/openalex-mcp-server/issues/114))
- **`openalex_research_landscape`** funding step groups by `funders.id`, which counts every work that lists a funder. ([#100](https://github.com/cyanheads/openalex-mcp-server/issues/100))
- **`openalex_describe_fields`** field catalog regenerated against OpenAlex's current field lists. ([#104](https://github.com/cyanheads/openalex-mcp-server/issues/104))
- **`openalex_resolve_name`** no-match notice names the `filters` that excluded the match. ([#103](https://github.com/cyanheads/openalex-mcp-server/issues/103))
- **Docker image** prunes musl-only native packages from the production dependencies; `server.json` npm entries launch the package bin through `npx`, and the HTTP entry sets `MCP_TRANSPORT_TYPE`.

## Fixed

- **`+` (AND within a field)** now ANDs; it went out percent-encoded and matched nothing. ([#107](https://github.com/cyanheads/openalex-mcp-server/issues/107))
- **Country and language filter values** are converted to the codes OpenAlex stores: on `country_code`, `country_codes`, and `countries` keys an alpha-3 code, numeric code, or English name becomes its alpha-2 code (`UK` becomes `GB`), and a `language` ISO 639-2 code or English name becomes its ISO 639-1 code. A country value that cannot be a code (`Germanyy`, `999`, `unknown`, `DE US`) fails as `invalid_country_code`; it used to match nothing, and its negation matched everything. ([#101](https://github.com/cyanheads/openalex-mcp-server/issues/101))
- **Multi-word values on exact-match keys** (`awards.funder_display_name`, `geo.city`, `raw_affiliation_strings`, and the like) are sent as one quoted phrase instead of matching nothing; a comma in them, or in a `.search.exact` value, is quoted rather than rejected. A value sent quoted that carries a `"` of its own fails as `quote_in_filter_value`. ([#113](https://github.com/cyanheads/openalex-mcp-server/issues/113), [#115](https://github.com/cyanheads/openalex-mcp-server/issues/115))
- **`id` and `seed_id` with a `.` or `..` path segment** fail as `id_dot_segment`; before, they reached a different OpenAlex endpoint. A `?` or `#` inside an identifier is sent percent-encoded as part of the ID. ([#109](https://github.com/cyanheads/openalex-mcp-server/issues/109))
- **An OpenAlex ID of another entity type** than the lookup's (or a concept ID) fails as `id_type_mismatch` before any request. ([#99](https://github.com/cyanheads/openalex-mcp-server/issues/99))
- **`filters` without `entity_type`** on `openalex_resolve_name` fails as `filters_without_entity_type`; every such call failed upstream. ([#105](https://github.com/cyanheads/openalex-mcp-server/issues/105))
- **Short names shaped like OpenAlex IDs** (keyword `p53`, `F1`, `S1`) fall through to the name search when the ID lookup misses. ([#106](https://github.com/cyanheads/openalex-mcp-server/issues/106))
- **Provider text** — MathType MTEF equation blobs are removed with the TeX that restates them, and a second cleanup pass no longer changes a result: an instruction target ended by a no-break space, an `<?MML` span measured before trimming, and a removal that joins text into a construct all converge in one pass. ([#92](https://github.com/cyanheads/openalex-mcp-server/issues/92), [#110](https://github.com/cyanheads/openalex-mcp-server/issues/110), [#111](https://github.com/cyanheads/openalex-mcp-server/issues/111), [#112](https://github.com/cyanheads/openalex-mcp-server/issues/112))
