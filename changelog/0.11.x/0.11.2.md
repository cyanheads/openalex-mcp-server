# 0.11.2 — 2026-11-17

## Fixed

- **`openalex_resolve_name` filter keys** are translated as `openalex_search_entities` translates them (`year` → `publication_year`, `cited_works` → `cites`, an `id` of OpenAlex IDs → `openalex` on works), with the same range checks. 0.11.1 sent keys as written, so `year` failed as `upstream_invalid_params`. ([#144](https://github.com/cyanheads/openalex-mcp-server/issues/144))
- **`id` filter on keywords** is no longer rewritten to `openalex` on any tool that takes `filters`; keywords have no `openalex` filter, and the rewrite sent a request OpenAlex answers with a 400. ([#144](https://github.com/cyanheads/openalex-mcp-server/issues/144))
- **A negative number at the top level of `filters`** (`{ "amount_usd": -5 }`) fails before any request on all four filter-taking tools, in both `OPENALEX_FILTER_RECORD_REPAIR` modes; 0.11.1 sent it as `amount_usd:-5`, which OpenAlex reads as the range at most 5. The string `"-5"` is sent as before. ([#142](https://github.com/cyanheads/openalex-mcp-server/issues/142))
