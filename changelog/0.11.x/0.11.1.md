# 0.11.1 — 2026-11-11

## Added

- **arXiv IDs** (`1706.03762`, `hep-th/9901001`, `arXiv:…`, arxiv.org `/abs/` and `/pdf/` URLs, `10.48550/arXiv.…` DOIs) resolve as work identifiers on `openalex_search_entities` `id` (works), `openalex_get_citation_graph` `seed_id`, and `openalex_resolve_name`. A version suffix is dropped and named in `notice`; a work OpenAlex holds under no arXiv DOI is found by its arXiv landing page, one list call billed. ([#137](https://github.com/cyanheads/openalex-mcp-server/issues/137))
- **Numeric filters** take `>=N`, `<=N`, `a..b`, `a..`, and `..b`, sent to OpenAlex as its hyphen ranges. ([#133](https://github.com/cyanheads/openalex-mcp-server/issues/133))
- **`filters` record** on all four filter-taking tools accepts boolean and number values, nested objects (`{"authorships": {"author": {"id": "A5…"}}}`), and quoted keys, normalized to string values under dotted keys and named in `notice`. `OPENALEX_FILTER_RECORD_REPAIR=false` restores string-only values. ([#136](https://github.com/cyanheads/openalex-mcp-server/issues/136))
- **`select`** accepts a comma-separated string on `openalex_search_entities` and `openalex_get_citation_graph`, and splits comma-joined array entries, each named in `notice`. `OPENALEX_SELECT_STRING_INPUT=false` requires an array. ([#135](https://github.com/cyanheads/openalex-mcp-server/issues/135))
- **Input aliases** `entity` → `entity_type`, `limit` → `per_page`, `work_id` → `seed_id` on the tools that take the target key. ([#138](https://github.com/cyanheads/openalex-mcp-server/issues/138))

## Changed

- **`select`** names that live under a top-level field return that field, with a notice: works `is_oa`, `oa_status`, `oa_url`, `any_repository_has_fulltext` → `open_access`, and a dotted name such as `primary_location.source.display_name` → `primary_location`. The `summary_stats` leaves (`h_index`) now carry the notice too. ([#135](https://github.com/cyanheads/openalex-mcp-server/issues/135))
- **`openalex_get_citation_graph`** gives seed resolution and the graph page one 50-second call deadline; a slow upstream fails as `upstream_timeout`. ([#137](https://github.com/cyanheads/openalex-mcp-server/issues/137))
- **Response metrics** — an `OpenAlex response metrics` record (route, parameter names, cost, remaining budget) is logged at `info` for every 2xx upstream response, $0 lookups included, in the process log only. The Docker image sets `MCP_LOG_RATE_LIMIT_THRESHOLD=0` so the framework's per-message rate limit does not drop them. ([#140](https://github.com/cyanheads/openalex-mcp-server/issues/140))
- **`openalex_describe_fields`** catalog regenerated: gains `is_traditional` (works filter and select), `awards_count` (authors and institutions filter and select), `awards_api_url` (authors and institutions select), `investigators.author.id`, `lead_investigator.author.id`, and `from_created_date` (awards filter), and the `to_created_date` and `to_updated_date` filters on awards, funders, institutions, keywords, publishers, and topics; loses `sustainable_development_goals_aurora` (works select). The generator leaves out filters OpenAlex refuses: works `semantic.search` and `topics_count`, sources `is_in_jstage_since_year`.
- **`@cyanheads/mcp-ts-core`** ^0.13.18 → ^0.13.22: error envelopes no longer carry the raw upstream `data.body` and `data.responseBody` (`upstreamMessage` and `upstreamError` remain), and `serverInfo` gains a `description`.
- **Framework skills and scripts** re-synced to mcp-ts-core 0.13.22.

## Fixed

- **Reversed numeric ranges** (`2024..2020`, `2024-2020`, `!2024-2020`) fail as `invalid_range_in_filter_value` before any request; 0.11.0 sent them and OpenAlex answered no records, or every record when negated. A negative bound and a `!` before a comparison or open range fail the same way. ([#133](https://github.com/cyanheads/openalex-mcp-server/issues/133))
- **`__proto__` key in a `filters` record** is refused in both `OPENALEX_FILTER_RECORD_REPAIR` modes; 0.11.0 dropped it silently, widening the query. With record repair on, a JSON-string `filters` holding whole numbers is accepted like the object form. ([#136](https://github.com/cyanheads/openalex-mcp-server/issues/136))
- **Wildcard 400s** from OpenAlex fail as `upstream_wildcard_requires_exact` (`*` or `?` in a stemmed works `query` or `.search` filter) and `upstream_wildcard_prefix_too_short` (fewer than three characters before `*`), each with its own recovery, where they were `upstream_invalid_params_other`. ([#134](https://github.com/cyanheads/openalex-mcp-server/issues/134))
- **`openalex_resolve_name`** returns field suggestions for an unknown filter key on an entity type, as `openalex_search_entities` does. ([#139](https://github.com/cyanheads/openalex-mcp-server/issues/139))
- **A rejected `group_by` key** on `openalex_analyze_trends` gets suggestions from the groupable fields only, so none fails a group_by retry (`publication_dat` suggests `publication_year`, not `publication_date`).
- **PMCIDs** resolve as identifiers on every tool that takes one; OpenAlex now indexes them, so the "not indexed" recovery is gone.
- **Keyword slugs** are documented as unbilled by-ID lookups.
