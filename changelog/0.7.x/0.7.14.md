# 0.7.14 — 2026-09-19

## Added

- **Input aliases** — `filter` → `filters` on `openalex_search_entities`, `openalex_resolve_name`, `openalex_analyze_trends`, and `openalex_get_citation_graph`; `search` → `query` on `openalex_search_entities`; `name` → `query` on `openalex_resolve_name`. Rewritten only when the declared key is absent and not advertised in `inputSchema`.

## Changed

- **Session mode** — the server now declares `stateless` as its HTTP session-mode default in code; an explicitly set `MCP_SESSION_MODE` still overrides it. The Docker image and `.env.example` already pinned `stateless`.
- **Tool error `content[]` text** now ends with `(reason <reason> · not retryable)` (or `· retryable`) whenever the error carries a `data.reason` or a boolean `data.retryable`. The `Recovery:` line is dropped when the message already contains the hint word for word. `structuredContent` is unchanged.
- **Argument-validation rejections** carry `data.reason: "invalid_arguments"` and a `Recovery:` hint derived from the schema, and an omitted required field reads as missing rather than as a wrong choice.
- **Tool arguments now pass a pre-validation step** before schema validation: undeclared root keys a client adds are dropped, key spellings differing only by case/`-`/`_` are rewritten, and a JSON-stringified array is repaired once after a failed parse.
- Framework skills, scripts, issue templates, and CI workflow synced with mcp-ts-core 0.13.1–0.13.5 (adds `.github/workflows/codeql.yml`, a README version-badge packaging check, and `config/`-aware build tsconfig probing); `withRetry`'s per-attempt signal now reaches `fetch`, and two handlers' precondition checks moved into module-level helpers.
