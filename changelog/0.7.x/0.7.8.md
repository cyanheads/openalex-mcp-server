# 0.7.8 — 2026-07-26

## Fixed

- **`openalex_search_entities`'s `id` lookup no longer rejected by search-only validations** — `semantic_per_page_cap`, `sample_with_cursor`, and `seed_without_sample` ran before the `id` branch, so a valid ID lookup carrying an unrelated combination (e.g. `search_mode: "semantic"` with `per_page: 100`) was rejected on constraints the singleton path never reads. The three checks are now scoped to list queries (`id` absent, by truthiness — an empty-string `id` still validates); the existing dropped-parameter notice reports the ignored parameters instead. All three contract entries remain reachable on the no-`id` path. ([#61](https://github.com/cyanheads/openalex-mcp-server/issues/61))
